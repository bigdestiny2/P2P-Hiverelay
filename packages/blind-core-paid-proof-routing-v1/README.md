# Private CORE paid-proof routing v1

This unused private successor fixes one runtime routing gap: an already paid CORE.PROVE can replay its exact committed result after a newer head activates, including after a fresh process restart. It inherits the accepted checkpoint storage engine and runtime adapter without changing those files, public selectors, schemas, wire/WAL bytes or the accepted real Hypercore package. The original committed-result branding, coordinator, admission preparation and body authority remain in use.

Use `BlindCorePaidProofStorageV1` with `BlindCorePaidProofRuntimeV1` and the exact real upstream profile recorded in `source-bindings.json`. The new package is a monorepo source component, not an independently installed/distributed package; it uses the exact root lock and the upstream package's exact private lock. No dependency or root export was added. Run `npm test` from this directory after both existing locks are installed. `npm run check:bindings` verifies all eleven consumed predecessor source/lock bindings. Binding changes require an explicit reviewed successor; the check never rewrites them.

## Route and authority

Before admission preparation, `inspectCheapState` asks storage for **size metadata only** from a live committed paid-proof pin. It compares the independently recomputed relay-bound commitment and full canonical request bytes, including admission token/profile/parameter bytes. This second comparison matters: the public CORE serve commitment intentionally excludes the admission token. The lookup performs a bounded scan over the existing configured pin map (default maximum 4096), exposes only three integer sizes, and never reads a corpus or materializes proofs. Unknown or free requests follow the original active-head inspector.

After the unchanged AdmissionCoordinator validates the request and produces its prepared spend, the runtime independently selects its exact retained size. Storage verifies the prepared profile matches the request and delegates spend/op/commitment, terminal and generation checks to the parent. Full canonical request matching is repeated before the parent can read a retired body. Original storage then locks the spend, checks pin expiry, materializes the immutable pinned corpus, checks exact proof length/hash and returns the original signed acknowledgement. It creates no new PROVE pin/charge on replay. A supplied earlier size that disagrees with the committed size is refused. Fresh execution checks the active generation before estimating or materializing it.

Input request, commitment and prepared-admission buffers are copied synchronously before any await. The inherited bounded flight coalescer still owns duplicate in-flight requests. There is no new persistent cache, alternate spend ledger, body reference, caller-verdict authority or hydration path. The operations execute/replay hooks are internal coordinator hooks; calling them directly is not a replacement for cryptographic admission validation and resource reservation at the public coordinator.

## Evidence and limits

Tests use real Hypercore11.34.1/Corestore7.11.1 stores, encrypted writer blocks and genuine key-only replication/proofs. The unchanged BlindOperationCoordinator, AdmissionCoordinator, DescriptorState and ResourceBudget process actual canonical dispatch frames. Descriptor/admission-parameter/result signatures are real. The token issuer/verifier is an explicit bounded test fixture with a whitelist and deterministic spend tags; this does not qualify a production admission scheme or an external operator.

The matrix covers exact charged retry after append/storage restart, unchanged full dispatch after fresh offline Node restart, current-head paid/free requests, higher-fork lower-length activation, unknown/mismatched token/profile/parameter/key/fork/length/head/sample/nonce/spend/operation refusal, caller Buffer mutation, conflicting reserved size, generation-owner callback and closed-store fences, concurrent coalescing while another head activates, pin expiry before and during admission, actual budget refusal, retained-proof substitution and cancellation. Retired corpus reads are instrumented at the real storage method and must occur with a live coordinator budget reservation. No source connection or active-corpus estimate occurs for the offline retry.

This qualification is local Node22.22.0 on macOS arm64. It does not qualify native OS owner/session deployment, TLS/DHT transport, independent hosts, Bare/Pear3.4, production token issuance, async public client proof verification, native OPEN, G04 body installation/pruning/hydration, total RSS/native-disk bounds or fleet rollout. Fresh-request real-upstream estimation still uses the predecessor's active corpus lookup and its component resource limits; this lane adds no pre-admission retired-body work and does not claim to solve all upstream preallocation limits. Existing metadata maps are trusted storage-owned state; no new index is installed. Large configured pin scans retain their original capacity/CPU qualification gate.

The upstream dependency was explicitly pending when this lane was locked. Its exact d0d88ba3 source subsequently received independent acceptance; the separate run evidence records strict acceptance consumption/revalidation. Neither the original pending lock nor sealed predecessor evidence was rewritten. This routing successor still requires its own independent acceptance. `status().productionReady` and `defaultSelected` remain false.

## Migration and rollback

No on-disk format migration is applied: the parent remains the only WAL writer, and exact head/corpus/proof bytes remain the accepted private HC11 profile. Existing stores can be opened by the private subclass under the same parent ownership constraints; this is not permission to install it on production data. Removing this package before selection restores the unchanged prior source. A later production selector/profile rollout needs separate compatibility, retained-body custody and rollback qualification. The fixed runtime retry behavior will be absent if a future rollback selects the predecessor runtime.
