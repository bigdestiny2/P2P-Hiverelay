# Private checkpoint format 2.0 and participant interface 1

This is lane A of the accepted snapshot-history readiness: a contract, canonical codec and deterministic vector component. It proposes **private internal-store format major 2, minor 0** for independent acceptance. It installs no runtime selector and grants no migration, hydration, pruning, HC11, release or production authority. The accepted `758013f6` component remains a full-genesis-WAL implementation with frozen format 1.2. The accepted production contract remains `63373bc7`.

The major version is deliberate: complete role hydration and pruned recovery contradict the predecessor's recovery-only snapshots, genesis-WAL retention and unsupported migration rules. `format-authority-v2.json` contains the exact ordered grammar, row keyspace, limits, rules, frozen codec/source pins and successor validator digest. Its canonical UTF-8 JSON ends in LF. `vectors-manifest.json` records its BLAKE2b format hash and all vector SHA-256 digests. No artifact in this directory replaces a predecessor.

## 1. Encoding and selection

`packages/blind-protocol/checkpoint-format-successor/codec.js` is imported by explicit private filesystem path only. Existing package exports, package files, root metadata and runtime imports are unchanged. Every new struct requires exactly its declared own fields; absent required fields, extra fields, invalid enums, bad magic, unknown version/hash, noncanonical compact lengths, invalid optional markers and trailing bytes refuse. Integers are unsigned fixed-width big-endian; u64 JavaScript values require bigint. Arrays and bounded bytes use the unchanged compact-uint length prefix; optional uses one 0/1 byte. Hash fields are nonzero bytes32. `Snapshot` is at most 256 MiB, each role at most 262,144 rows; each CORE group at most 65,536 rows. These are refusal ceilings, never a license to silently discard records. Deployment capacity can impose lower limits.

The `Snapshot` magic is `HRBCS002`. Header fields bind exact format hash, installation/root/role, relay/store/continuity, covered WAL sequence and hash, writer map generation/epoch/fence hash, epoch/descriptor/clock/recovery-gap floors, cumulative history, snapshot revision/predecessor hash, compaction WAL high-water and retention floor. Exactly one of CELL, INBOX or CORE payloads must match role 1, 2 or 3. These role codes are distinct from frozen wire/storage family tags CELL=2, INBOX=3, CORE=4. A root ID is an installation-assigned opaque identifier, never a path; shared storeId alone is insufficient role identity. All references must be rebound to retained file/owner identity before use.

Snapshot hash is BLAKE2b-256 of ASCII `hiverelay.blind.checkpoint-snapshot.v2`, U64BE byte length and exact canonical Snapshot bytes. Format hash reuses frozen `hashStoreFormat`. Participant hash uses the analogous domain `hiverelay.blind.participant-authority.v1`. `artifactBytes()` returns a copy. The hashed validator pin makes executable contract checks reviewable; it does not authenticate a running process.

Existing v1 manifest/checkpoint layouts have explicit format-major/minor/hash and snapshot hash/length fields. A later explicitly selected format-2 runtime may reuse these outer byte layouts if it verifies those fields and role/root binding before decoding `HRBCS002`. This lane does not alter their magic, MAC/signature recipes, filenames, slots, WAL frames, readers or selection policy. A current runtime must refuse format 2; the helper `compatibility()` returns policy descriptions and is not a reader or migration executor. Format 1.2 input still requires its exact frozen artifact, identities and full-genesis reader; a version number alone never authenticates it.

## 2. Mandatory cumulative history

`History` holds the role's monotone irreversible bit, installation authority sequence/record hash and immutable first-trigger hash reference. Irreversible state requires an existing first trigger. False may coexist with a trigger caused by another participant. Positive paid state must not claim false history. Empty live maps do not establish false. For the first successor of a full-WAL predecessor, a real accepted engine reducer derives history from authenticated complete WAL, including paid OPEN_STATE. For later snapshots, history is predecessor-history OR valid suffix triggers. CELL legally retired history remains true after GC and legal COMPACT; INBOX/CORE retained control evidence must remain present because no removal transition is accepted for them.

The authority reference in a capture names an **already durable ancestor** installation history record, not the record that will later cover this same snapshot. Publication builds snapshot, checkpoint and manifest first, then a new participant record can cover their hashes. This avoids a circular snapshot/authority hash. Recovery requires the referenced ancestor, the later covering record, original first-trigger bytes and authenticated installation ancestry; equality with the newest record alone is insufficient. First-trigger bytes are retained externally in the installation authority namespace and compared by their frozen hash recipe; fixtures cannot supply fresh authority.

`assertSnapshotSuccessor()` rejects identity/predecessor/WAL regression, cleared or replaced first trigger, history record sequence forks, epoch/descriptor forks, writer/retention regression and illegal CORE evidence removal. It is a deterministic data relationship check, not a semantic replay, floor witness, signature verifier or runtime capability. The real coordinator additionally validates durable floor, lease, descriptor lineage, reducer transitions, custody and exact suffix coverage. A copied MAC-valid installation can be stale: local copied records alone cannot detect a wholly self-consistent stale copy. Independent retained floor/lease/witness or externally pinned restore evidence is necessary for that stronger claim.

## 3. Per-role complete state

CELL and INBOX reuse their named frozen canonical row codecs. `Row.kind` and `subtype` select the exact `rowCodecs` table; `Row.key` contains only the identity suffix of the predecessor family/subtype key. `rowKeys` fixes the identity recipes: spends/retries use spendTag; request results use requestCommitment; CELL uses storageSlot; INBOX uses physicalTopic with U64BE appendRevision for frames; retry frame pins use spendTag with U64BE revision; integrity evidence uses evidenceHash; the mandatory global has an empty identity. Sort is unsigned byte order of kind, subtype, identity, with no duplicates. The role supplies the frozen family prefix when composing the predecessor semantic validator. No arbitrary map serializer is introduced.

Capture drains/refuses provisional and reservation rows and nonzero staging/reserved accounting. Global epoch, clock-unsafe and recovery-gap must match the envelope. Snapshot state must preserve canonical spends, commitment/result indexes, retry lifecycle/pins/material, terminal evidence, frame/opaque body references and complete accounting under pinned `cell-control-snapshot.js` and `inbox-control-snapshot.js`. CELL includes the engine's compaction high-water and actual anti-replay horizon. INBOX has no new control-map compaction. The codec verifies named values, key correspondence, ordering and selected relationships; full semantic reconstruction/joins, configured quotas and physical body checks are mandatory in lane B. A structurally decoded row set is not a complete engine state capability.

CORE has six sorted row groups and an exact derived summary:

| Group | Complete retained information |
| --- | --- |
| Admissions | Globally unique spendTag, operation MIRROR/PROVE/OPEN, canonical prepared admission: profile/scheme/parameter/resource/lease/cost/request commitment and original WAL commit material. Exactly one operation owns every admission. |
| Mirrors | Canonical request and signed ACK, paid spend, accepted epoch and WAL tuple, original acceptance basis and its origin tuple, target lease, candidate revision, virtual bucket, latest lifecycle tuple, ACCEPTED/RETRY_PENDING/ACTIVE/TERMINAL, retry count/reason and terminal reason. |
| Generations | Core key and activation revision, activating mirror spend/WAL, previous activation key, exact fork/length/signed head/lease/activation epoch and opaque corpus reference (bucket/object/length/hash). Historical ACTIVE mirrors and generations remain even when a later generation replaces them. |
| Floors | One durable latest generation key per core, active/inactive flag and retained expiry epoch/WAL evidence when inactive. Fork/length/lease metadata is obtained from the retained generation; an inactive floor is not a live body owner. |
| Proofs | Paid original challenge and signed ACK, original source generation, pin WAL, proof length/hash, pin/expiry times and optional expiry WAL/time. An expired proof retains its admission and full source evidence; it is a spend tombstone and no longer a live corpus owner. |
| Opens | Canonical frozen reserved/live/terminal OPEN retry snapshot plus prepared admission and lifecycle WAL. Preserve logical retry/spend/request/channel/stream indexes, parent binding, class limits, nonce, result and terminal reason. Recover reserved/live under existing terminalization; never resurrect upstream ports, tickets or children. |

The prepared admission is reused by exact named private codec and byte order; its exports are unchanged. Requests/results use existing frozen codecs. The successor explicitly validates request commitments, role identity, descriptor floor, deterministic CORE virtual bucket, MIRROR billable class/accepted basis, PROVE full encoded result band, OPEN logical/request/session/channel tuple, and retained evidence/accounting. Decode does **not** validate signed ACK/OPEN signatures, admission token authority, trusted time, descriptor lineage or file contents. Lane B must use existing result domains, canonical unsigned bytes and relay identity to validate signatures; historical descriptor references must be authenticated against lineage rather than compared blindly to the newest descriptor.

Candidate revision begins at zero and follows the highest pending candidate or durable floor at acceptance. Activation revision separately begins at zero and advances the last activated durable floor. The basis receipts are therefore separate. Real replay verifies the actual then-pending set and activation order; mere existence of a supplied basis is not proof. Source migration must retain/derive missing basis and activation evidence from authenticated full WAL before pruning. A proof can reference an older replaced or expired source; requiring the current generation would reject valid state.

Reconstruct indexes and compare the declared six counts. activeCores is the active floor count; liveProofPins excludes expired pins. Live corpus ownership is the unique union of active floors and live proof sources, with no disagreement for the same bucket/object. Sum each owned body's byte length once. controlBytes=512*(mirrors+opens); proofPinBytes=1024*liveProofPins; tombstoneBytes=256*expiredProofs. Maximum corpus size is 64 MiB with deployment limits potentially lower; proof payload is at most 4 MiB minus 256 and complete encoded result must fit the frozen 4 MiB band. Pin lifetime is positive and at most 900,000 ms. This successor requires expiry evidence to demonstrate the deadline was reached; the predecessor's expiry reducer alone did not establish that timestamp.

The current CORE maps discard PROVE admission/pin evidence after expiry and omit acceptance/activation/expiry provenance. Capturing today's maps alone therefore cannot produce this payload. Lane B must retain those records during genuine replay/capture, or reconstruct them from authenticated full WAL or a previously accepted successor snapshot. No fabricated map deletion, synthetic retirement or assertion of completeness is permitted.

Snapshot successor checks retain immutable MIRROR request/result, admission-linked spend, acceptance basis/WAL, candidate revision and target lease. ACCEPTED can become RETRY_PENDING, ACTIVE or TERMINAL; retries increment their bounded count and may update their reason. Unchanged retry counts retain their reason. ACTIVE and TERMINAL rows are final. Changed lifecycle evidence must be in the successor suffix. At a retained floor generation, active can become expired once with suffix expiry evidence; inactive cannot reactivate or replace that evidence. A later genuine activation can advance the floor generation, while all historical generation rows remain. These are data relationships, not authentication or proof of real suffix transitions.

Retained OPEN rows preserve every identity field: version, logical retry key, spend tag, request commitment, wire profile, session class, client nonce, parent session, control channel, parent binding, stream ID, class limits, opened epoch and virtual bucket. Same-state rows must remain byte-identical, including lifecycle WAL/hash, result and terminal reason. Only RESERVED→LIVE/TERMINAL and LIVE→TERMINAL may change state, with lifecycle WAL sequence in `(previous.coveredWal.sequence, next.coveredWal.sequence]`. Any non-null result must be the exact retained bytes. A transition to TERMINAL may use the frozen null-result shape; no replacement result is authorized. TERMINAL rows are thereafter immutable. This preserves the predecessor codec terminal/null-result allowance and does not claim every allowed structural transition was produced by recovery: actual `#terminalizeRecoveredOpens` preserves the previous result bytes. Lane B must validate the real suffix reducer evidence.

Newly expired PROVE likewise requires expiry WAL in `(previous.coveredWal.sequence, next.coveredWal.sequence]`. Original pin WAL/hash, source, request/ACK, proof identity, pin time and deadline remain immutable; the existing pin-before-expiry and deadline predicates still apply. Already-expired rows retain identical expiry WAL/hash/time and cannot reactivate. No wall-clock freshness or authenticated suffix claim follows from these data-level checks.

CORE relationship joins use canonical identity indexes after sorted-unique validation, avoiding a history scan per retained row. The ordinary capacity regression contains 128, 512 and 2,048 mirrors/generations/proofs/OPEN rows, with three times as many admissions and one latest floor; it records actual encoded bytes and timing on each qualified target. It also deterministically rejects a return to per-record `some`/`find` joins on the retained groups. This is bounded synthetic regression evidence, not qualification of the 65,536-row or 256 MiB ceilings as production capacity.

Populated CELL and INBOX vectors are derived from the frozen semantic snapshot test fixtures through the actual predecessor entry producers and reconstruction validators. CELL preserves committed staged PUT, atomic PUT, retained terminal spend, renewed metadata and two opaque body references. INBOX preserves CREATE/APPEND/READ/terminal spend, a frame and retry reconstruction/material/pin rows; a separate predecessor expired-APPEND fixture retains its exact ACK/control evidence without a frame. The one reserved row in each source fixture is drained to terminal state with exact accounting. These are synthetic fixture states, not API-produced storage histories or evidence of a new retention policy. Their canonical entries are mapped by removing the frozen family/subtype prefix and carried unchanged into the successor row payload; Python compares those family value bytes opaquely and does not reconstruct family semantics. The producer harness loads the protected CELL dependency closure, including a source-matching retained native module, but opens no store and calls no native storage function.

## 4. Engine-owned capture, hydration and suffix interface

`participant-contract.d.ts` describes future private ports. It supplies no runtime implementation or usable brand constructor. Real authority must be held in module-private WeakMaps bound to object identity, root/role, open file identities, retained OS ownership, writer lease/fence, format, barrier and authenticated installation view. A copied/serialized/type-cast object must fail. No public `fromState`, arbitrary successful validation callback or caller-owned map can mint capture, shadow, suffix or coverage authority.

Capture drains each real engine's admission/persistence, body publication, MIRROR/proof adapters, expiry, OPEN lifecycle and CELL/INBOX provisional work while retaining ownership and a stable WAL barrier. It obtains exact engine state and WAL tuple atomically, captures cumulative history/floors/compaction/retention bookkeeping, validates live opaque bodies and quotas, and produces a detached capture. A cancelled/failed drain must not yield a positive capture; outstanding work remains retained until genuinely drained or closed.

Restart first opens every participating blind root under native ownership and verifies manifests, checkpoint lineage, snapshots, history references and common installation authority read-only. Each real engine builds a detached shadow at its own anchor. Verify any retained covered frames mechanically against the anchor without applying them twice, then apply only frames above the anchor using real private reducers. Verify genesis is present for format 1.2; format-2 authorization must prove the missing prefix is covered. Cumulative sequence is u64; observed retained frames/bytes are separately bounded (262,144 and 256 MiB ceilings). A sequence of 300,001 or u64 maximum with no suffix does not itself consume that many observed frames. Refuse overflow and excessive work before allocation or mutable recovery.

Revalidate live corpus/frame/cell hashes, quota/accounting, parent/body ownership, leases, floors, source tuples and handoff identity before truncation, orphan cleanup, sweeps, OPEN terminalization or visibility. Only an engine-validated shadow plus joint verified authority may be adopted. Retain store ownership throughout handoff and all cancellation/close paths. Verified reader integrity and writer availability are distinct; quarantine never becomes a writable success through cached positive replies.

## 5. Publication and pruning authority

Future publication order is: capture under drain/barrier; encode bounded snapshot; exclusive temporary write and fsync; semantic/identity verification; native no-replace final install; directory sync and readback; immutable checkpoint header through the same process; advance the exact linked manifest slots using existing CAS order; sync and verify both references; publish/confirm any required covering installation participant record; revalidate lease, files and semantic capture; then mint a live root/role/anchor-specific coverage handle. Existing local checkpoint helpers are reusable mechanics but not all-role engine authority.

A `CoverageBinding` serializes identity/writer/format/WAL/snapshot/checkpoint/manifest/revision/history/retention descriptions only. A `ReplayBinding` additionally records head and observed work budgets. Neither can authorize pruning. The live coverage handle must prove complete cumulative history, retained spend/retry ownership, actual predecessor coverage, anti-replay horizon and still-held owner identity. Only it can authorize removal of fully covered sealed-prefix segments, oldest first, with a directory sync after each unlink. Keep the live WAL segment and every final snapshot/checkpoint file. No checkpoint-history GC or new INBOX/CORE control retention is part of this first component. If retained state or ancestry reaches configured limits, refuse before unsafe work; never clear it to fit.

Uncertain publication preserves temporary/final evidence and quarantines all participants; no positive result is returned until the exact durable commit point is known. For shared history, immutable record namespace sync is the durable commit point; a mutable head may lag and is recovered by validating the committed record chain. Terminal transport cancellation cannot release storage ownership or convert an interrupted mutation to success. Stop timeout/reentry must retain or retry the exact pending cleanup and not create a second owner.

## 6. Typed HC11 installation history

`Participants` has magic `HRBPA001`, installation ID, revision/predecessor hash, immutable first-trigger reference, sorted unique blind coverage records and optional typed HC11 activation evidence. Blind entries carry role/root/store/continuity/format and their own WAL/checkpoint/snapshot tuple. HC11 carries root, authenticated envelope manifest hash, database identity hash, activation key, exact length=1/fork=0, activation block hash and original trigger receipt hash. HC11 has no blind WAL fields. Never coerce Corestore append indexes into a blind sequence/hash or expose Hypercore internals as substrate data.

The shared interface records the first irreversible fact, per-blind-role captured coverage and actual HC11 activation identity. It is **not** an every-append high-water ledger and does not prove retention of every later HC11 append or blind ACK. Lane C must wire actual guarded Corestore ready, sentinel append/read, envelope identity and common coordinator publication/acknowledgment with failure quarantine across all participants. Corestore/Bare/Pear engine deployment is unproved here. An HC11 fixture with plausible hashes is a structural example, not actual activation evidence.

`assertParticipantsSuccessor()` preserves installation/first-trigger lineage, role identities, monotone blind coverage/history and the exact original HC11 activation evidence. No participant removal/rebind/migration is introduced. Missing roles required by configured topology must refuse even though the generic codec permits one to three blind roles and optional HC11. Topology selection is authenticated coordinator policy, never inferred from files that happen to be present.

## Compatibility, migration and rollback

| Input / action | Required behavior |
| --- | --- |
| Exact frozen 1.2, intact genesis WAL | Existing accepted reader and authority only; no new behavior from this directory. |
| Frozen 1.2 with missing prefix | Refuse; an old recovery-only snapshot is insufficient. |
| Exact candidate 2.0 / candidate codec | Bounded decode/structural relationship checks only; no engine opening or authority. |
| Candidate 2.0 / current runtime or legacy writer | Refuse unsupported selection; no source downgrade or fallback. |
| Unknown magic/version/hash/schema/role/key | Refuse without store mutation. |
| 1.2 → 2.0 | Later explicit offline migration contract must first authenticate full WAL, retain original trigger/evidence, produce complete role state, stage immutable artifacts and commit selection under ownership. No executor here. Missing PROVE provenance must be reconstructed before any prune. |
| Interrupted migration / uncertain CAS | Preserve evidence and owner lifetime, quarantine, re-read exact durable state. No assumed rollback from a thrown promise. |
| 2.0 pruned → 1.2 | Refuse; an older reader lacks history/hydration semantics and cannot recreate genesis. |
| Pretrigger pristine rollback | Only an independently authorized gate with intact predecessor evidence; no migration performed here. |
| After first blind-only write (D7) | Legacy-only operation forbidden. G05 must prove authorized dual-reader rollback, old-writer exclusion and inner-path/device rebind; acceptance of these codecs does not grant it. |
| Closed whole-copy restore | May reproduce a closed byte-identical store; not pruned hydration or stale-copy detection. |
| Authenticated pruned restore | Requires lane B actual publication/physical deletion/engine hydration and lane C joint participant authority. |
| Stale whole-installation backup / new device | Requires independent floor/lease/witness/restore proof and G05 qualification. Copied local MACs do not establish freshness. |

## Acceptance and remaining lanes

Lane A acceptance checks exact source/artifact pins, deterministic generation, canonical roundtrips/refusals, history and identity/floor regressions, paid OPEN lifecycle, retained expired PROVE, historical ACTIVE generations, pending/terminal MIRROR, u64 versus observed-work budgets, typed participant evolution and unchanged protected predecessors. Cross-language qualification compares 32 positive payloads using independent Python encoding/decoding and BLAKE2b snapshot/participant hash calculations. Family `Row.value` bytes are deliberately opaque predecessor payloads in that grammar; this does not claim an independent Python engine validator. All vector signatures and opaque body/receipt bytes are synthetic and confer no authority. Negative cases are deterministic codec/relationship refusals, not exploit/security validation.

Lane B must implement actual three-root capture/publication/pruning/hydration with accepted interfaces, preserving current full-WAL behavior. Require API-driven CELL staged/atomic PUT→GC→legal COMPACT; INBOX CREATE/APPEND/RENEW/CLOSE/expiry with retained retries; CORE MIRROR activation/replacement/expiry, PROVE pin/expiry and paid OPEN-only reserved/live/terminal. Physically delete a covered sealed prefix through the published coverage coordinator, prove genesis absent, reopen actual engines, compare maps/counts/floors/retry results/live opaque bodies and apply suffix exactly once. Cover multiple checkpoints, empty suffix, conservative pretrigger recovery and original first-trigger bytes. Refusal cases inventory all files before/after.

Lane B/C qualification must kill/reopen at drain, snapshot/header sync/install, each manifest slot, participant record sync/head lag, every prune unlink/sync, shadow validation, tail repair, adoption and first post-restore write. Include stale/foreign/role/floor/semantic/body/lease faults, bounded high sequences, concurrent family writes, cached positive retries and stop timeout/reentry. Lane C provides real blind+HC11 joint acknowledgment/restore; G05 remains its downstream rollback/rebind gate. Node macOS/Linux process/container tests are not native-device power-loss proof. No Bare/Pear packaged daemon, OS install, fleet, device or production target is qualified by this lane.
