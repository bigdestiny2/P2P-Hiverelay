## Draft CHANGELOG entry

Insert at the top of CHANGELOG.md, above the v0.8.19 entry:

```markdown
## [0.8.20] — 2026-05-23

Anchor honesty + custody auto-attestation. Two related fixes that close
the "relay claims to serve content it doesn't have" failure mode and
finally wire up the cryptographic loop for blind-custody BURNED state.

Both shipped by community contributor [@iainkek](https://github.com/iainkek)
([PR #19](https://github.com/bigdestiny2/P2P-Hiverelay/pull/19) +
[PR #20](https://github.com/bigdestiny2/P2P-Hiverelay/pull/20)), with
production validation against the milkyb-fra Fly.io relay.

### Anchor honesty (PR #19)

**The bug:** Relays were setting `anchored=true` whenever
`drive.version > 0` — i.e., whenever metadata had synced — not when
the actual blob blocks were present locally. Three call sites
(`_eagerReplicate`, `repairUnanchored`, `_runAnchorCheck`) all made
the same mistake. Because `runRepairPass` skips entries marked
anchored, any drive whose blob download timed out mid-pull was
silently locked out of self-heal indefinitely. End users hit
hangs-forever; operators bounced relays as a workaround
(`docs/FEEDBACK-PEARBROWSER-PIN-CAP-FAILURE.md` — the "may need a
bounce" recipe was lottery, not a fix).

This is orthogonal to v0.8.13 (cancellation contract) and v0.8.14
(per-drive corestore session). Those addressed stop()-triggered and
continuous-operation corestore-close vectors. This addresses the
anchor-flag-on-metadata-only vector that persists when a download
just doesn't complete cleanly, with no corestore-close in sight.

**The fix:** New `AppLifecycle._isDriveFullyReplicated(drive)`
helper that checks `drive.blobs.core.has(0, blobs.core.length)` —
the canonical hypercore bitfield-presence API. Returns true for
empty blob cores (metadata-only drives), false for closed drives,
missing blob layers, or any block gap. All three anchoring sites
now gate `setAnchored` on `downloadComplete && _isDriveFullyReplicated(drive)`.
`_eagerReplicate` stops silently swallowing `downloadWithTimeout`
errors. `_runAnchorCheck` does `clearAnchored` with a partial-pin
reason code when it catches a downgrade. `repairUnanchored` returns
false on partial so the next repair tick re-queues.

**Live validation:** Deployed pre-merge to `milkyb-hiverelay-fra`
against the Drop drive that originally surfaced the bug
(`b6ad60e1` corroboration commit). 11/112 entries on that relay
were similarly downgraded by the new check, and self-heal pulled
the missing blocks on the next periodic cycle.

**Backwards compatibility:** Upgraded relays self-heal on the
first periodic anchor check after restart (≤10 min). Existing
`anchored=true` registry entries get downgraded to false if their
blob cores have gaps; `runRepairPass` then pulls the missing
blocks. No protocol/RPC/schema changes.

### Custody auto-attestation (PR #20)

**The gap:** Atomic Blind Custody had the cryptographic primitives
(`createCustodyNonServingProof`, `createCustodyExpiryWitness`) but
they were only invoked when something explicitly called
`/api/custody/{id}/non-serving-proof`. The periodic
`_runCustodyExpiryPass` deleted blobs cleanly on expiry but never
signed proof of having done so. Recipients probing for BURNED
state always got `QUORUM_UNAVAILABLE` because no proofs existed.

**The fix:**

1. **Auto-emit `custody-non-serving-proof` on expiry.** The expiry
   pass now captures `custodyIntentId + blindContentId` BEFORE
   `unseedApp` (since unseed removes the entry and
   `createCustodyNonServingProof` would otherwise throw
   `STILL_SERVING`), then signs + records a non-serving-proof for
   each expired entry. Skips silently for pre-pipeline blind
   entries without custody linkage. Surfaces attestation failures
   via `custody-non-serving-attest-error` event without failing
   the unseed.

2. **Cross-relay expiry-witness pass.** New
   `_runCustodyExpiryWitnessPass` scans all known custody intents
   past their `retainUntil` and signs an independent
   `custody-expiry-witness` attestation for every peer relay's
   non-serving-proof observed via registry gossip. Recipients now
   get dual cryptographic confirmation:
   - relay-X self-signs "I deleted my copy" (proof)
   - relay-Y independently witnesses "I observed relay-X's signed
     deletion" (witness with `nonServingProofHash`)

   Threshold-many witnesses give the recipient a BURNED guarantee
   resistant to a single relay self-attesting falsely. Refuses
   self-witness (`SELF_WITNESS_REFUSED`), deduplicates by
   (witnessPubkey, relayPubkey, intentId), opt-out via
   `config.custodyWitnessEnabled = false`.

3. **Composed scheduling.** Both passes run on the same interval
   tick (default 60s) via a `runBoth` closure in
   `_startCustodyExpiryMonitor`. Initial pass also fires 5s after
   start, same as before.

### Tests

- `test/unit/repair-loop.test.js` — 6 new tests covering partial-pin
  state, empty blob core, closed drive, missing blob layer,
  requeue-after-downgrade (PR #19)
- `test/integration/partial-pin-self-heal.test.js` — 4 new
  integration tests using real `Corestore` + `Hyperdrive`; test 2

  on-disk shape of a real partial pin (PR #19)
- `test/unit/relay-node.test.js` — 8 new tests covering auto-emit
  happy path, no-intent skip, attest-error handling, witness happy
  path, self-skip, dedup, retainUntil gate, refuses-own-proofs
  (PR #20)

All 18 new tests pass locally. Adjacent suites (anchor-status,
anchor-proof, anchor-channel, lifecycle-scope, drive-close-cascade,
repin-cap-reconcile, cancellable-drive-update, app-registry,
app-registry-provenance, blind-path-airtight, custody-signing) all
still pass.
```

### Anchor-honesty soak observation (PR #19 in action)

The first periodic anchor check after restart (≤10 min) will downgrade
false-anchored entries on each relay. Expect to see:

- `clearAnchored` events in journalctl (`journalctl -u hiverelay --since "10 min ago" | grep clearAnchored`)
- `anchored` counter in `/status` to drop temporarily, then climb back
  as `runRepairPass` pulls missing blocks
- For relays that had hidden partial-pin issues, this is when they'll
  surface — that's the fix working as designed, not a regression

Capture a baseline before/after for the rollout retro:

```bash
# Before each restart, capture pre-deploy anchor count:
for h in 144.172.101.215 144.172.91.26 104.194.153.179 104.194.152.121 45.59.123.112; do
  ssh_cmd="ssh -o ConnectTimeout=8 root@$h"
  [ "$h" = "104.194.152.121" ] || [ "$h" = "45.59.123.112" ] && ssh_cmd="ssh -i ~/.ssh/cloudzy_hiverelay -o ConnectTimeout=8 root@$h"
  $ssh_cmd "curl -s http://127.0.0.1:9100/catalog.json" \
    | python3 -c "import json,sys; d=json.load(sys.stdin); apps=d.get('apps',d if isinstance(d,list) else []); print('$h anchored_pre={}/{}'.format(sum(1 for a in apps if a.get('anchored')), len(apps)))"
done
```

"false-anchor" rate the bug was hiding.
