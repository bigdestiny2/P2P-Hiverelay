# Private CELL and INBOX full-WAL capture

The explicit `storage-engine-checkpoint-v1.js` and `inbox-storage-engine-checkpoint-v1.js` siblings add static `captureFullWal(options, {lease, requiredAnchor, limits, maximumRows})`. `readBlindCellWalCapture` / `readBlindInboxWalCapture` accept only the original per-module token, exact root and retained native transaction lease. Default engines, selectors, package exports and accepted format/source bindings remain unchanged. This is a prerequisite for the joint checkpoint coordinator, not its implementation.

Each capture replays the complete genesis WAL through the actual private engine reducers in an unopened shadow. It refuses provisional/reserved state, staging/reservation accounting, recovered quota or integrity gaps, torn tails and excessive observed work. It then uses the frozen family entry producer and semantic reconstruction joins to validate canonical rows, retaining their exact values and identity keys. CELL captures its real compaction high-water and remaining spend floor; INBOX permits no new spent-state compaction. Both preserve irreversible history from original reducers even after live body retirement.

Refusal ceilings are262144 retained rows,262144 observed WAL frames and256MiB observed WAL or encoded row bytes; callers may choose lower row/work bounds. Per-frame checks use constant-time top-level map sizes; complete nested pin counts are checked once before encoding. Existing per-frame codec and WAL byte limits still apply. These are conservative component ceilings, not qualified production capacities. Capturing large histories still requires later operational capacity qualification.

Scan handles and shadow cleanup finish before final file/lease revalidation and token minting. Reads repeat file validation and then a final native ownership check before copying values. No exported helper can mint a capture. A copied token, another root/lease, replaced or changed scanned files, or ownership released during awaited checks must refuse. The helpers do not expose a live mutable engine or return arbitrary caller-owned maps as authority.

Captured body references are descriptive only. No body is decrypted, copied, created, removed or repaired; hashes/physical files, installation ancestry, descriptor lineage, authentic admission authority and common generation identity still require the joint coordinator. Captures do not authorize publishing snapshots, pruning covered WAL, hydrated recovery, installing another reader, changing an identity or writing to a fleet. Closed full-WAL scans refuse provisional work rather than performing mutable recovery to make capture possible. Live three-root admission/drain/body barriers and authenticated restored shadows remain required.

The qualification uses actual storage API histories, native local ownership, exact family reconstruction, original engine behavior tests, and independent review. It covers staged and atomic CELL, real retirement/COMPACT, finalized and provisional INBOX APPEND, retained exact expired ACK rows, pristine roots, copied evidence, bounds, wrong anchors, torn tails and file-check/shadow-close ownership races. Initial test development failures are retained: Brittle requires exception.all for TypeError and the actual WAL filename is wal.v2. These fixture corrections do not alter store behavior. Node/macOS evidence does not qualify Bare/Pear3.4, Linux, physical power-loss, supported devices or fleet release.

Removal of these unselected private files requires no data rollback. The full0.27 requirements and their independent runtime, recovery, privacy, consumer, soak, signing and fleet gates remain active.
