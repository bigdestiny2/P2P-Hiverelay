Node Operator Dashboard Design

What data matters when a HiveRelay node is fully stood up for the giga substrate (blind cells, Tor, namespace/OutboxLog, WAL, T1 gateway) and first apps like Peerit. Builds on the existing dashboard shell (dashboard/index.html + Network / Payments / Blindspark) and the APIs already exposed (/health, /status, /api/overview, Prometheus).

Operator job: keep a conduit healthy, compliant, and economically viable — without becoming a content curator or leaking privacy-sensitive topology. The dashboard answers five questions at a glance: Am I up? Am I full? Am I exposed? Am I useful? Am I in legal/ops trouble?

2. Information architecture

Home · Pulse Roles & Claims Storage & WAL Apps & Namespaces Transports · Privacy Gateway · T1 Custody · Blind Compliance · Takedown Economics Alerts · Audit

Auth model (keep): public /health + bounded /status for probes; management-authenticated /api/overview, /api/health-detail, admin takedown, accounting, subsidy. Dashboard UI is localhost or reverse-proxy with injected UI token (existing pattern).

Never show on public/status surfaces (redaction ladder): full onion addresses, restricted-discovery rosters, client-auth pubkeys, raw PEERIT_READ_KEY, release signing seeds, unredacted peer IPs of private clients, plaintext outbox contents, per-user social graph. Public metrics get coarse health only for Tor (ready / degraded / down).

Compliance Suppression count (keys / appIds); last takedown ts; admin auth enabled?; backup age; restore drill last success Legal readiness; “can I comply in minutes?” Management + audit log
Economics Subsidy accrued/today/cap; payout destination set?; credits; invoices; lease occupancy Why run the node; coordinator claim prep Management
Fleet identity Node pubkey; region; channel (canary/stable); release tag; capability doc hash Multi-node ops; “am I the version the roster expects?” Pubkey public; rest management
Alerts health-warning / health-critical stream; disk thresholds; Tor degraded; WAL interior break; rate-limit storms Actionable attention without watching graphs all day Management
What operators should not need: post titles, report reasons, moderation tallies, user handles, decrypted bodies. Those are app semantics. The node shows plumbing. If Peerit moderation is “working,” the proof is client-side; the operator only needs outbox throughput, suppress list, and backup health.

9. Implementation path (pragmatic)

  1. v0 — now: Keep current dashboard; add disk + role chips + suppression count to Pulse (fields largely in status/overview already for disk/uptime).
  2. v1: Namespaces card + compliance panel (OutboxLog + suppress APIs) + Tor public health enum.
  3. v2: WAL + shard Prometheus panels; gateway panel when enabled; negative-probe bit. (shipped)
  4. v3: Fleet multi-node view (read-only aggregate of many /status); never merges private Tor detail. (shipped: GET /api/fleet + /fleet dashboard; config.fleet.peers)
