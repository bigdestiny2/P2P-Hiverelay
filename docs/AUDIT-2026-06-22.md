# HiveRelay Core3 Audit - 2026-06-22

## Scope

Audited the local `hiverelay` Core3 tree with attention to security,
performance/optimization, user-facing operational UX, and release propagation
to the raw fleet, Umbrel packaging, and StartOS packaging.

## Findings And Fixes

- Dependency audit found vulnerable lockfile entries:
  - `protobufjs <= 7.6.2` in the production dependency graph.
  - `js-yaml <= 4.1.1` in the dev/lint dependency graph.
  Both are fixed in `package-lock.json`; `npm audit` now reports zero
  vulnerabilities.

- Re-audited the dependency cleanup roadmap item that marked
  `@grpc/grpc-js` and `@grpc/proto-loader` as unused. Current code still uses
  both through dynamic imports in the optional LND `LightningProvider`, and
  operator docs already describe gRPC as the LND integration path. The roadmap
  now keeps those packages as intentional Lightning payment dependencies while
  preserving the lazy startup path for relays that never connect an LND node.

- Lazy-loaded the interactive `@inquirer/prompts` dependency inside the setup
  and manage TUI entrypoints. The main CLI already dynamically imports those
  command modules, and now importing either module for docs/tests does not load
  the prompt package until `runSetup()` or `runManage()` actually starts.

- Re-audited the Noble crypto dependency cleanup item. `@noble/secp256k1` and
  `@noble/hashes` are not ZK-only: the core relay uses them for PVSS blind
  custody verification, the client uses them for PVSS split/reconstruct, and
  the services package uses them for identity/ZK. Core did not import
  `@noble/curves`; that dependency is now removed from `p2p-hiverelay` and
  remains owned by `p2p-hiveservices` for VRF and poker Ed25519 curve logic.

- Removed the hardcoded StartOS build `VERSION` from `startos/Makefile`. The
  Makefile now derives its default from the root `package.json`, while still
  allowing `make VERSION=...` for local overrides. `release:prepare` continues
  to synchronize StartOS manifest/README release metadata, but no longer needs
  to rewrite the Makefile for a version-only bump.

  fallback still supports actual localhost development, but now requires the

  Origins, and remote sockets are rejected before management auth succeeds.

  return the same 401 shape as other management routes and increment

  metrics instead of failing silently with a private 403 path.

- Hardened auth-failure observability labels. The central 401 route label now
  strips query strings before metrics/logging, collapses long hex identifiers,
  and sanitizes control/quote/odd characters so debugging URLs with `api_key`

- Hardened relay identity secret-file creation. Node RelayNode and BareRelay
  now write first-boot identity material to owner-only temporary files and
  atomically rename them into place with a random sodium-backed temp suffix
  that does not depend on Node-only `process` globals in the Bare/Pear path.
  This replaces writing the long-lived relay signing key with default process
  permissions and chmodding afterward, removing the first-start window where a
  permissive umask, crash, or failed chmod could leave the identity seed
  broadly readable.

- Gated the alert log endpoint behind management auth. `GET /api/alerts` can
  include health, policy, service, and auth-failure details, so unauthenticated
  callers now get the central 401/auth-failure metrics path while authenticated
  operators can still inspect recent alerts.

- Gated self-heal diagnostics behind management auth. `GET /api/health-detail`
  exposes health-check internals and recent self-heal actions, while
  `GET /api/auto-heal` exposes archive-tier recruitment/backoff state; both now
  use the central 401/auth-failure metrics path.

- Gated raw dashboard history behind management auth. `GET /api/history` returns
  the in-memory metrics snapshot ring, which stores full `getStats()` snapshots
  for dashboard charts; unauthenticated callers should use public aggregate
  `/metrics`, `/health`, `/status`, catalog, or capability endpoints instead.

- Hardened operator read-query parsing. Integer query values for catalog
  pagination, storage-top count, alert offset/limit, and history minutes now use
  one strict clamping helper, so malformed values such as `1e9` or `10abc`
  fall back safely and huge/negative values cannot expand history windows or
  create negative alert slices.

- Hardened operator numeric write parsing. Management config writes, mode
  overrides, and device-pairing timeouts now require plain safe integer values
  for integer fields and plain decimal values for bandwidth fields, rejecting
  partial/exponential/blank strings such as `12abc`, `1e9`, `12.5` where an
  integer is required, or blank/exponential bandwidth values. `/api/manage/config`
  now also rolls back earlier in-memory numeric field edits when a later field
  in the same request is invalid, preventing a 400 response from leaving unsaved
  runtime drift.

- Hardened dedicated gateway catalog parsing. The separate public data-plane
  `GatewayServer` now uses the same strict bounded integer model for
  `/catalog.json` pagination, rejects invalid `type=` filters with a 400
  instead of broadening the response to the full catalog, and supports
  `gatewayPort: 0` for deterministic local tests.

- Hardened the Hyperdrive HTTP gateway request parser. `/v1/hyper/*` now
  rejects unsupported methods with `405 Allow: GET, HEAD`, catches malformed
  direct or double-decoded percent-encoded paths as 400s instead of allowing
  them to bubble into 500s, preserves double-encoded traversal rejection, and
  parses byte ranges as decimal digits only so JavaScript forms such as
  `bytes=1e3-`, `+1-3`, or decimal offsets cannot be accepted as valid
  byte positions.

- Fixed Hyperdrive gateway timeout cleanup. Successful drive operations now
  clear and `unref()` their timeout handles instead of leaving 30-second timers
  alive after every fast gateway read, improving high-volume gateway request
  churn and making shutdown/test teardown reflect real outstanding work.

- Hardened oversized management API JSON handling. `_readBody()` now stops
  accumulating data after the 64 KiB cap, drains/ignores the rest of the
  request, and returns a stable JSON 413 with `Connection: close` instead of
  destroying the request socket before the client can receive the error.
- Extracted bounded JSON request-body parsing into
  `packages/core/core/relay-node/api-body.js`. The management API keeps its
  existing `_readBody()` wrapper and response mapping, while
  `test/unit/api-body.test.js` directly covers empty bodies, malformed JSON,
  top-level array/primitive rejection, oversized drain behavior, and stream
  errors. Top-level JSON arrays, null, strings, booleans, and numbers now
  return `JSON body must be an object` before route mutation code can interpret
  ambiguous shapes.

- Hardened POST `Content-Type` validation for chunked requests. The API now
  parses the media type exactly (`application/json` with optional parameters)
  instead of substring-matching JSON-looking values such as `application/jsonp`
  or `text/plain; application/json`. It also treats `Transfer-Encoding` as
  evidence of a body, so chunked JSON without `Content-Type: application/json`
  is rejected by the global gate before auth or body parsing. Early body
  rejections return `Connection: close` so unread request bytes cannot leave a
  reusable HTTP connection in an ambiguous state.
- Extracted POST media-type gating into
  `packages/core/core/relay-node/api-request.js`. The route dispatcher now
  delegates to `getPostJsonContentTypeProblem()`, while
  `test/unit/api-request.test.js` directly covers empty POSTs, valid JSON with
  parameters/case variation, JSON-looking media types, missing content type on
  chunked bodies, and the close/no-close decision for early body rejection.

- Hardened `RelayAPI.stop()` and dashboard feed teardown. API shutdown now
  awaits WebSocket feed close and force-closes active HTTP connections around
  listener shutdown. This prevents shutdown/restart from hanging on clients
  that keep an active request or dashboard socket open after an early body
  rejection or interrupted upload.

- Hardened dedicated gateway shutdown. The data-plane `GatewayServer` now
  tracks active HTTP sockets, clears rate-limit state, closes idle/all
  connections where supported, and destroys held sockets during stop so heavy
  gateway reads or half-open clients cannot indefinitely delay relay restart.

- Bounded RelayNode startup DHT flush. The relay still joins/announces on the
  DHT, but startup now treats the initial `swarm.flush()` as best-effort with a
  default 1s timeout so local health checks, the dashboard, Umbrel/StartOS app
  proxies, and fleet restart gates are not held offline by slow public
  bootstrap. Timeout and error events remain observable for operators.

- Fixed config-loader nested default aliasing. `loadConfig()` previously left
  nested default objects shared with the live config object; mutating
  `config.subsidy.payoutDestination` also mutated `defaults.subsidy`, causing
  `saveConfig()` to consider the wallet destination unchanged and omit it from
  `config.json`. The loader now deep-clones merged config values, and the
  wallet/config/service save endpoints await config persistence before
  returning success.

- Hardened config persistence failure reporting for Umbrel-facing save flows.
  `_persistConfig()` now returns the saved path on success, emits
  `config-persist-error` and rethrows write failures, and wallet/config/service
  save routes roll back in-memory edits and return a 500 `persist-failed`
  response before showing UI success. This prevents a read-only or full data
  volume from making Add Wallet or Save Services appear to work when the next
  restart would lose the change.

- Hardened wallet/wizard persistence synchronization. `/api/subsidy/destination`
  now saves the first-run wizard payout state before returning wallet success,
  reports wizard-file write failures as `persist-failed`, and restores saved
  wizard state if the following config write fails. Add Wallet therefore no
  longer leaves `config.json` and `wizard.json` disagreeing after a disk or
  permissions failure.

- Hardened live subsidy payout persistence. `SubsidyAccrual.setPayoutDestination()`
  now rejects explicit destination writes when its atomic state file cannot be
  written and restores the previous in-memory destination. The Add Wallet API
  treats that as `persist-failed` too, then restores the already-saved config
  and wizard files so `config.json`, `wizard.json`, and `subsidy.json` do not
  silently diverge.

- Hardened remote service-protocol pub/sub subscriptions. Remote peers can no
  longer send wildcard/glob topics such as `poker/*` or `*`, cannot create
  duplicate subscriptions for the same topic, and are capped to 64 requested
  topics per message / 128 tracked subscriptions per peer. PubSub capacity
  errors are now surfaced as `subscription-error` events instead of escaping
  the message handler. Peer detach/destroy cleanup is now explicit and
  idempotent: subscriptions, rate-limit buckets, peer roles, and pending RPCs
  are removed immediately even if the underlying Protomux close callback is
  delayed or absent in a fake channel.

- Optimized P2P app-catalog fan-out. Service peers still receive a full app
  catalog on channel open, but live seed/unseed broadcasts now send
  `MSG_APP_CATALOG_DELTA` with signed additions and remove hints instead of
  re-sending the whole catalog for one-app churn. Relays process only the
  signed additions for remote auto-seed/review flows; removals update client
  caches and never remotely unseed operator content.

- Hardened proof-of-relay challenge accounting. The old roadmap item about a
  broken custom Merkle verifier is now resolved in code and docs: Hypercore
  owns flat-tree integrity, while proof-of-relay checks nonce/core/index,
  latency, data presence, bounded block size, and nonce-keyed hashes when the
  challenger already knows the block. Pending challenge state now has a hard
  `proofMaxPendingChallenges` cap and challenge batches have a
  `proofMaxBatchSize` cap, so a verifier cannot grow pending proof state
  unboundedly during large challenge bursts.

- Hardened authenticated unseed verification. `verifyUnseedRequest()` now
  rejects non-safe-integer and negative timestamps before building the signed
  payload, so malformed fractional or unsafe timestamp values return
  `MALFORMED_REQUEST` instead of throwing through `BigInt()`. The focused
  unseed verifier tests now cover valid signatures, wrong publishers, stale
  and future timestamps, missing publisher keys, invalid signatures, malformed
  keys/signatures, and malformed timestamp values.

- Completed the shared Core3 constants cleanup for current protocol surfaces.
  `core/constants.js` now owns the seed, circuit, forward, and services
  Protomux channel names alongside the existing discovery topics,
  `isValidHexKey()`, `compareVersions()`, and `uint64ToBuffer()` helpers. The
  client SDK, seed/circuit/forward/service protocol modules, main CLI, and
  catalog CLI now import those shared constants/helpers instead of retaining
  local wire-name or hex-regex definitions.

- Shared the service-protocol message framing between relay and client. The
  relay now exports `serviceMessageEncoding` and `MAX_SERVICE_MESSAGE_BYTES`
  from `core/services/protocol.js`, and the client SDK uses that encoding for
  its `hiverelay-services` channel instead of carrying a local copy. Oversized,
  malformed, short-header, and truncated service frames now reject the same way
  on both sides without throwing. The shared decoder also rejects invalid
  decode state, including missing buffers, negative starts, unsafe offsets, and
  inconsistent end bounds, as a protocol error instead of letting Buffer offset
  exceptions escape the message handler.

- Anchor, custody, and publisher-submit channels now use the same bounded JSON
  Protomux encoder as the service channel, with channel-specific byte caps and
  the existing protocol error strings preserved. This removes three remaining
  inline `readUInt32BE(state.start)` decoder copies and gives proof, custody
  push, and publisher-submit fast paths the same malformed-frame,
  short-header, truncated-payload, oversized-frame, and invalid decoder-state
  no-throw behavior.

- The registry metadata channel now uses that same bounded encoder, and the
  helper rejects oversized outbound messages during `preencode()`/`encode()`
  before growing compact-encoding state or writing a frame. This keeps local
  announce/catalog/publish paths from allocating oversized Protomux buffers
  that the receiver would reject anyway.

- Full integration/Bare gates were not run in this audit pass.
- The sibling `blindspark-umbrel-store` checkout is currently on a different
  release line (`0.19.0`) than local `hiverelay` (`0.16.3`). The new release
  script detects and can synchronize it, but publishing should intentionally
  choose the desired release line.

  `FLEET_SSH_PRIVATE_KEY`. This local audit only dry-ran the inventory/target
  resolution; it did not SSH into the production relays.
- Official Umbrel marketplace publication still requires Umbrel review/PR flow.
  Full releases require the community-store and official-PR credentials, but
  this local audit did not push to the store or open the upstream PR.
- StartOS `.s9pk` is built, verified, uploaded to the GitHub Release, and
  registry-published during full releases with the required StartOS credentials.
  This local audit did not publish to a StartOS registry. Official Start9
  marketplace/community registry inclusion still requires Start9 review.
