Giga Release Architecture — Where We Are Now

Date: 2026-07-19 · Supersedes: GIGA-RELEASE-ARCHITECTURE export dated 2026-07-17/18 · Posture: giga substrate largely shipped on integration lines; freeze holdouts remain; Peerit is the first live application canary on the relay plane

This is the composition map of the release as it stands today: five HiveRelay giga subsystems (blind cells, Tor onion transport, HTTPS gateway, namespace, WAL) plus the first application path — Peerit standing on blind-capable relays. Compared with the mid-July architecture export, WAL phases 1–3, Tor pairing/peer-vport follow-ups, namespace bytesPerDay, gen-3 Hypercore, and Peerit’s writable public canary have all moved.

What changed since the previous architecture export

  • WAL: phases 1–3 shipped on the blind/v1-integration line (2026-07-18) — group commit, single-commit atomic PUT, segmented WAL + pruning. Previous doc: phases 1–3 “not implemented.”
  • Tor: pairing-channel onion enrollment + peer-vport listener binding landed (69a51dde).
  • Namespace: bytesPerDay enforced with rolling 24h window (d9bdb405).
  • Hypercore gen-3: Hypercore 11 / Corestore 7 / Hyperdrive 13 upgrade on HiveRelay.
  • Gateway app origins: Phase-1 canary + G1–G6 evidence executed (G7–G13 still operator/fleet).
  • Peerit: public writable canary on peerit.site + outbox.peerit.site (HTTP 200 verified 2026-07-19); single-ingress canary, not GA.
  • Programme machinery: pear-agent-system, shared adoption lanes, preservation bundles (2026-07-18), blind×Peerit qualification labs.

Design invariants (unchanged): relays are blind (content and keys stay at the edge), authorization is signature-based (transport never grants authority), privacy claims stay on their ladders (each lane advertises only what it can evidence).

6. WAL — from gate-in-flight to nearly closed

The WAL is the blind custody store’s write-ahead log (wal.v2, magic HRWL) on the blind / v1-integration line (not mainline hiverelay package tree). It provides atomic one-use spend, fsync-before-ack durability, fail-closed recovery, writer fencing, continuity hash, and epoch floor.

PhaseContentStatus (now)
0 — measurecapacity model + portable harnessesDone (macOS; Linux fleet rerun still required)
1 — group commitbatching + fdatasync + preallocationShipped 2026-07-18 · f0b4376 · ~8k concurrent commits/s macOS
2 — single-commit PUT3 frames → 1 atomic staged pathShipped 2026-07-18 · 290bebd · 1,841→971 B/PUT
3 — segmented WALpruning + checkpoint-anchored recoveryShipped 2026-07-18 · 76eff20 · walPruningSupported: true
4 — model rerunscenarios with measured constantsPartial (Phase 0); Linux constants pending

Follow-up (not freeze gate): under 64-way concurrency, atomic PUT still serializes on quota:atomic-staging (~35 vs ~126 PUTs/s) — narrow lock scope before relying on P1×P2 composition at scale.

Do-not-overclaim: WAL lives on the blind/v1-integration line; macOS numbers only until Linux Phase-0 fleet rerun lands; mainline p2p-hiverelay@0.24.3 consumers still need explicit pin to the blind daemon profile that carries WAL.

The monumental task is not “finish five features in isolation.” It is running a blind-capable relay profile that a real app (Peerit) can use in production without overclaiming. Substrate features are largely code-complete on their lanes; the remaining work is evidence-bound promotion: fleet numbers, operator contracts, multi-ingress durability, and GA-grade Peerit gates.

9. Final test matrix — what still means “test everything out”

  1. Per-feature suites — unit/e2e green for blind, tor, gateway path, namespace, WAL P1–P3 macOS.
  2. Cross-feature journeys
    • k-of-n cells over Tor onions → receipts → reconstruct (blind × tor)
    • public app via gateway while custody hard-403s (gateway × tor)
    • two apps / two namespaces on one relay with takedown (namespace × blind)
    • Peerit signed commits over OutboxLog while PearBrowser peers still converge offline
  3. Adversarial / privacy — fail-closed downgrade, redaction audits, orphan-pin, cross-namespace replay (verified 2026-07-18). Gap: private onion negative-probe.
  4. Release-gate holdouts
    • Linux WAL Phase-0 fleet rerun
    • App-origin gateway G7–G13
    • 100 MB bulk-over-onion measurement
    • Peerit: second operator, 2 000-client staging, device proofs, content cleanup, CSP
