What was cut into the tag

  • Tor packaging defaults — Docker / systemd / Umbrel set HIVERELAY_TOR=1 (host Tor still required on systemd fleet).
  • Utility services default-on in packaging — outboxlog, notify, storage-proof, VRF, witnesslog, repairticket; shard-store opt-in for large disks.
  • Service HTTP wiring — VRF /api/v1/vrf/*, notify push resolution, client helpers, dashboard notify/VRF panels.
  • Outboxlog durability — journal / lifecycle fixes covered by unit tests.
  • Ship ladder — docs/LADDER-SHIP-MAP.md (Track A fleet vs Track B blind public-test vs later merge).

Why canary is not on rc.1

The v0.25.0-rc.1 tree imported gateway modules that were not in the tag (exact-app-context, hive-host, …) and had a duplicate resolveStorageCap export. Canary boxes crash-looped. Canary channel on GitHub main was held back to v0.24.3. Fixes live on feat/service-http-wiring for a future rc.2.

03Three tracks (don’t mash the versions)

Utility substrate

Channels, systemd boxes, Docker/Umbrel packaging. Today’s live code is v0.24.3. Tag v0.25.0-rc.1 was cut for canary then held. Tor + utilities can be enabled on boxes without waiting for 0.25 process.

syd-1 + dal-1

06Honesty board — say this, not that

OK to sayDon’t say
We cut a canary prerelease v0.25.0-rc.1 and documented it; canary is held on 0.24.3 while we fix the tag. Stable fleet is on 0.25.
Two large relays run Tor onions + full utility services. The whole fleet is Tor-hidden.
Blind public-test is a parallel pilot (syd/dal) with a Peerit bind scaffold. 0.25 is blind GA / blind is in the fleet tag.
Utility plugins are on for the cohort via services.json. Every HTTP surface from 0.25 is live (VRF HTTP needs fixed process).
G5 for public content is impossible — we never claim it. Active-reader resistance on public data.
